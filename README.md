# Swish Studio Finder

Two-step city → studio finder with a persistent Google Map, built for the Swish Dental Webflow site.

Designer-native: all markup lives in Webflow as a component, driven by `data-sf-*` attributes. The marketing team maintains content in the CMS and Designer without touching this repo.

Same delivery pattern as the existing `hmpsn/swish` map bundle - GitHub repo, tagged release, loaded from jsDelivr, config passed in via a global set before the script.

## Files

| File | Purpose |
|---|---|
| `studio-finder.js` | The finder. Commented source, no build step. |
| `studio-finder.css` | Behavioural CSS only - view switching, dropdown anchoring, popup animation. Visual styling stays in Webflow. |

## Usage

In Webflow, Page Settings → Inside `<head>`:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/hmpsn/studio-finder@1.0.0/studio-finder.min.css" />

<script>
  window.SF_SETTINGS = {
    googleMapsApiKey: 'YOUR_RESTRICTED_KEY',
    googleMapId: 'YOUR_MAP_ID'
  };
</script>

<script defer src="https://cdn.jsdelivr.net/gh/hmpsn/studio-finder@1.0.0/studio-finder.min.js"></script>
```

`.min.js` / `.min.css` are generated by jsDelivr on request - only the unminified sources are committed. Drop the `.min` if you want to read the served file while debugging.

**Never commit the API key.** It lives in Webflow page code so it can be rotated without cutting a release.

## Releasing

```bash
git add -A && git commit -m "…"
git tag 1.0.1 && git push origin main --tags
```

Then update the two `@1.0.0` strings in Webflow to `@1.0.1` and publish.

Always load by tag, the way `swish-map.js` does. A tag URL is immutable and cached permanently; a branch URL is cached by the CDN and cannot be reliably force-refreshed, so a bad push would be stuck live with no way to pull it back.

Rollback is a one-line change: point the two URLs at the previous tag and publish.

## Page setup

The finder boots from the element carrying `data-sf`.

| Attribute | Value | Effect |
|---|---|---|
| `data-sf` | (present) | Marks the finder root. One per page. |
| `data-default-city` | empty | Two-step: Choose a City → Choose a Studio |
| `data-default-city` | a market slug (`austin`) | Lands directly in that city, Previous Step hidden |

On the shared Webflow component, `data-default-city` is bound to a component property so each page sets its own value.

## Constraints

- `studio-finder.js` and `swish-map.js` must never run on the same page. Two map stacks on one page means two vendors billed.
- Leave the Collection Lists inside the component unfiltered. The script does the filtering; a Designer filter breaks the counts and the region list.
- Slugs that match no market fall back to the two-step overview.
